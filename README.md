# Корсик — демо-бот адаптации для MAX

Прототип использует `maxapi` long polling, SQLite, контент из YAML и синтетический HRIS. При запуске обрабатывает `/start`, предлагает привязку по демо-коду, поддерживает `/Food` и `/HR`, кнопки, демонстрационные опросы, таймлайн и CSV-экспорт. AI, внешние HR-уведомления и недостающие материалы остаются явно помеченными заглушками.

## Запуск за 5 минут (Windows / PowerShell)

1. Установите Python 3.11+ и `uv`.
2. Скопируйте `.env.example` в `.env` и заполните `MAX_BOT_TOKEN` токеном MAX. Настоящие токены не добавляйте в исходный код.
3. Из каталога проекта выполните:

   ```powershell
   uv sync
   uv run python .\main.py
   ```

4. Откройте диалог с ботом в MAX и отправьте `/start`.
5. Для демо-регистрации введите одно из кодовых слов:

   | Кодовое слово | Площадка | Категория |
   | --- | --- | --- |
   | `яблоко` | GrPP | офис |
   | `груша` | GTP | не офис |
   | `слива` | Luzhniki | офис |
   | `лимон` | GTP | офис |
   | `вишня` | GrPP | не офис |
   | `персик` | Luzhniki | не офис |

Код подтверждает только синтетическую запись в `mock_hris.json`. Сотрудник выбирает форму общения, после чего планировщик создаёт задания по таймлайну. Не добавляйте в mock HRIS реальные персональные данные.

## Демо-команды

- `/start` — регистрация или меню.
- `/Food` — подсказка об обеде и PDF-заглушка/материал для площадки.
- `/HR` — создать тикет и включить handoff.
- `/help` — справка по командам.
- `/stages` — этапы таймлайна и их статусы.
- `/next` — немедленно выполнить следующий ожидающий этап по порядку.
- `/jump <ключ>` — выполнить указанный этап, например `/jump d1_12_access`.
- `/me` и `/stats` — профиль и статистика сотрудника.
- `/reset` — сбросить демо-профиль и начать привязку заново.
- `/close <employee_code>` — закрыть handoff.
- `/simulate <номер>` — запустить этап по номеру (1–23).
- `/approve <employee_code> <day2|day3>` — подтвердить этап, ожидающий рекрутера.
- `/export_analytics` — создать восемь CSV-файлов в `exports/`.

В `DEMO_MODE=true` команды тест-режима доступны привязанным сотрудникам. В обычном режиме доступ ограничивается `ADMIN_USER_IDS`.

## Быстрый ручной проход

1. `/start` → `яблоко` → подтвердить профиль → выбрать «На ТЫ» → ответить на вопрос о транспорте.
2. Несколько раз вызвать `/next`, чтобы пройти расписание по порядку; аудитории, которым этап не подходит, будут пропущены.
3. Проверить ветку по доступам: `/jump d1_12_access` → нажать «Нет».
4. Проверить финальный опрос: `/jump final_survey`, затем пройти вопросы. Ответ об уходе создаёт красный флаг.
5. `/reset` → `/start` → `груша` или `слива` для проверки других площадок.

## Материалы

Положите доступные файлы в `assets/`; если файла нет, при `SHOW_ASSET_STUBS=true` бот отправляет TODO-заглушку:

- `img_1.png` … `img_16.png`
- `postcard_1.png`, `postcard_2.png`
- `lunch_GrPP.pdf`, `lunch_GTP.pdf`, `lunch_Luzhniki.pdf`
- `presentation.pdf`, `adaptation_plan.pdf`
- `events_1.jpg`, `events_2.jpg`

Настройки времени: `TIMEZONE=Europe/Moscow`; `TIME_SCALE=1` — реальное время, `TIME_SCALE=0.000694444` приблизительно ускоряет сутки до минуты. Изменения `.env` применяются после перезапуска.

## Архитектура и проверка

- MAX API используется только в `monitor/bot/max_adapter.py`, на основе примеров `maxapi`.
- FSM, опросы, help/handoff, тест-команды и отправка сценарных этапов находятся в `monitor/flows.py`; таймлайн — в `monitor/timeline.py`.
- Фильтры аудитории и реестр этапов — `monitor/stages.py`; загрузка файлов и заглушки — `monitor/assets.py`.
- Тексты — `content/messages.yaml`, опросы — `content/surveys.yaml`.
- SQLite-таблицы и расширения старой схемы создаются при старте.
- Для проверок выполните `uv run python -m compileall -q main.py monitor tests scripts`, `uv run python -m unittest discover -s tests` и `uv run python scripts/check_scenario_texts.py`.
