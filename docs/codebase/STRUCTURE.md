# Структура проекта

## Карта файлов и каталогов

| Путь | Назначение |
|---|---|
| `main.py` | Точка входа: инициализация SQLite, создание адаптера и обработчиков, запуск задач и polling |
| `monitor/config.py` | Переменные конфигурации, разрешение путей, фабрика реального или mock LLM-клиента |
| `monitor/bot/max_adapter.py` | Единственная активная граница MAX API и `maxapi` |
| `monitor/flows.py` | FSM регистрации, обработчики сообщений и callback, опросы, handoff, красные флаги, команды |
| `monitor/storage.py` | CRUD-функции для сотрудников, состояний, сообщений и тикетов |
| `monitor/db.py` | Инициализация и миграции SQLite, загрузка mock HRIS |
| `monitor/timeline.py` | 25 таймлайн-заданий, расчёт времени, обработка готовых задач |
| `monitor/analytics.py` | Выгрузка восьми псевдонимизированных CSV |
| `monitor/rag/` | PDF/TXT-индексация и поиск/ответы RAG; сейчас выключается настройкой и обходит основной путь при выключенном флаге |
| `monitor/agents/`, `monitor/alerts/` | Отдельные старые AI/уведомительные реализации; напрямую из `main.py` и `flows.py` не вызываются |
| `monitor/bot/delivery.py` | Старый HTTP-клиент MAX, не используется активным `MaxAdapter` |
| `monitor/pipeline/scheduler.py` | Старый планировщик на `onboarding_templates`, не используется `main.py` |
| `monitor/scripts/` | Утилиты подготовки/импорта демо-данных; не входят в обычный запуск |
| `db/schema.sql` | Базовые определения таблиц SQLite; `init_db()` дополняет старые таблицы миграциями |
| `content/messages.yaml` | Шаблоны сообщений, группировка по сценариям и форме обращения |
| `content/surveys.yaml` | Определения этапов и вопросов опросов |
| `mock_hris.json` | Синтетические пользователи, offer binding-коды и псевдонимы `E-000N` |
| `data/` | SQLite-файл и RAG-индекс/материалы, если соответствующие данные присутствуют |
| `tests/test_demo_flows.py` | Интеграционные тесты пользовательских потоков с FakeAdapter и временной БД |
| `README.md` | Локальный запуск и команды демо |
| `OPEN_QUESTIONS.md` | Неутверждённые решения и заглушки |
| `docker-compose.yml` | Конфигурация Docker Compose; обычная инструкция запуска использует `uv run`, а не Compose |

`uv` создаёт `.venv/`; это окружение, не исходный код и не часть архитектуры приложения.

## Точки входа

- Основная команда: `uv run python .\main.py` из каталога проекта.
- В `main.py` вызывается `asyncio.run(main())`.
- В `main()` загружается SQLite и запускается `MaxAdapter.run()` с long polling.
- Дополнительных активных worker-процессов в точке входа нет.

## Границы модулей

| Граница | Должна владеть | Не должна владеть |
|---|---|---|
| `max_adapter.py` | MAX-объекты, преобразование входных событий, polling и отправка | Бизнес-правила регистрации и опросов |
| `flows.py` | Сценарии, решения по FSM и событиям | MAX-specific типы API; общается через `MaxAdapter` |
| `storage.py` / `db.py` | SQL-доступ и схема | Тексты пользовательских сообщений и маршрутизация MAX |
| `timeline.py` | Расписание и статусы задач | Формирование MAX-клавиатур |
| `analytics.py` | Формирование и маскирование CSV | Работа с MAX-сообщениями |
| `content/` | Редактируемые тексты и вопросы | Код переходов FSM |

На практике `flows.py` остаётся крупным модулем и напрямую содержит часть SQL для опросов, red flags и напоминаний.

## Именование

Python-файлы и пакеты используют `snake_case`, классы — `PascalCase`, функции и методы — `snake_case`. Внутренние методы помечены начальным `_`. Нет обнаруженной настройки import alias или публичного barrel-export.
